M3(1)                          m3 Command Reference                         M3(1)

NAME
    m3 - local-first document analysis toolkit for qualitative research

SYNOPSIS
    python m3.py [--go | --batch FILE | COMMAND [ARGS...]]
    python m3.py batch-index  --project NAME --corpus PATH [OPTIONS]
    python m3.py batch-ingest --project NAME --corpus PATH [OPTIONS]  (deprecated)

DESCRIPTION
    m3 (monkey3) ingests documents (txt, md, pdf, docx), processes them through
    a 4-stage LLM pipeline (Stratify -> Structure -> Enrich -> Synthesis),
    stores embeddings in ChromaDB, and provides semantic search and analysis
    plugins.

    m3 operates in three modes:

    Interactive Mode  (--go)
        Persistent session with command aliases and history. All commands are
        prefixed with '/'. Managers are reused across commands for speed.

    Single-Command Mode
        Run one command directly from the shell. Managers are initialised fresh
        for each invocation.

    Batch Mode  (--batch FILE)
        Execute a sequence of commands from a text file. Lines beginning with
        '#' are treated as comments. Errors are reported but do not halt
        execution.

GLOBAL OPTIONS
    --go
        Enter interactive (REPL) mode. Displays a prompt with the active
        project name. History is saved to ~/.monkey3/history. Tab completion
        and auto-suggest are available.

    --batch FILE
        Execute commands from FILE sequentially. Each line is a command exactly
        as it would be typed in interactive mode (without the leading '/').

================================================================================
COMMAND GROUP: project  (/p)
================================================================================

Interactive alias: /p

project create NAME
    Create a new, empty project. In interactive mode the new project is
    automatically loaded as the active project.

    ARGUMENTS
        NAME    (required) Project name. Used as the directory name under
                ~/.monkey3/projects/.

    EXAMPLE
        python m3.py project create my_study
        /p create my_study

--------------------------------------------------------------------------------

project list
    List all available projects. The currently active project is marked with
    an asterisk (*) and highlighted.

    EXAMPLE
        python m3.py project list
        /p list

--------------------------------------------------------------------------------

project active NAME
    Set the active project for the current session. In interactive mode this
    re-initialises VectorManager and AnalyzeManager for the new project.

    ARGUMENTS
        NAME    (required) Name of an existing project to activate.

    EXAMPLE
        /p active my_study

--------------------------------------------------------------------------------

project remove NAME
    Permanently delete a project and all its data (corpus files, vector store,
    metadata). Prompts for confirmation before proceeding. If the deleted
    project was active, the session is unloaded.

    ARGUMENTS
        NAME    (required) Name of the project to delete.

    EXAMPLE
        /p remove old_project

--------------------------------------------------------------------------------

project dialogue [NAME]
    Start an interactive RAG chat session against the active project's vector
    store. Maintains conversation history for the duration of the session.
    Type 'exit', 'quit', or 'bye' to leave dialogue mode.

    Requires: interactive mode (--go) and an initialised vector store.
    If NAME is given and differs from the active project, that project is
    loaded first.

    ARGUMENTS
        NAME    (optional) Project to chat with. Defaults to active project.

    EXAMPLE
        /p dialogue
        /p dialogue my_study

COMMAND GROUP: corpus  (/c)
================================================================================

Interactive alias: /c

corpus add PATHS... [--type TYPE] [--ingest]
    Add one or more files, directories, or glob patterns to the corpus.
    Glob patterns must be quoted to prevent shell expansion.
    Files are registered in corpus_metadata.json. Without --ingest the
    vector store is NOT rebuilt automatically -- run 'index build' afterward.

    ARGUMENTS
        PATHS   (required, variadic) One or more of:
                  - File path:       /data/interview.docx
                  - Directory:       /data/transcripts/
                  - Glob pattern:    "data/*.txt"
                  - Recursive glob:  "data/**/*.md"
                  - Mixed:           file.pdf "notes/*.md" some_dir/

    OPTIONS
        --type TYPE
            Document type as defined in config.yaml (ingestion_config.
            known_doc_types). Defaults to ingestion_config.default_doc_type
            (typically 'document').

            Common values: document, interview

        --ingest
            After adding all files to the corpus, immediately run the full
            4-stage pipeline to build the vector index. Equivalent to
            'corpus add ...' followed by 'index build'.

    EXAMPLES
        /c add report.pdf
        /c add "transcripts/*.docx" --type interview
        /c add "data/**/*.txt" notes/ report.pdf
        /c add interview_02.docx --type interview --ingest

--------------------------------------------------------------------------------

corpus remove IDENTIFIER
    Remove a file from the corpus by its original filename or corpus ID.
    Does not automatically rebuild the vector store.

    ARGUMENTS
        IDENTIFIER  (required) Original filename or SHA-based corpus ID.

    EXAMPLE
        /c remove interview_01.docx

--------------------------------------------------------------------------------

corpus list
    List all files registered in the active project's corpus.

    OUTPUT COLUMNS
        ID            38-character corpus ID (SHA-256 prefix)
        Chunks        Number of vector store chunks for this file
        Document Type Document type (document, interview, etc.)
        Original File Original filename

    EXAMPLE
        /c list

corpus provenance IDENTIFIER
    Show the full provenance record and version history for a document,
    including all tracking metadata recorded during ingestion.

    ARGUMENTS
        IDENTIFIER  (required) Original filename or corpus ID.

    OUTPUT FIELDS
        Corpus ID         Internal SHA-based identifier
        Original Path     Absolute path at time of add
        Doc Type          Document type used during ingestion
        Hash (SHA-256)    Content hash for change detection
        Added At          Timestamp of corpus add
        Ingested At       Timestamp of last vector store build
        Pipeline          Pipeline variant used (e.g., cogarc)
        Chunk Count       Number of chunks in the vector store
        Text Cache        Path to cached plain-text copy
        Version History   Prior versions if the file was replaced

    EXAMPLE
        /c provenance interview_01.docx

    DEPRECATED. Use 'corpus restore' instead.
    Kept as a hidden backwards-compatible alias; emits a deprecation warning.

    EXAMPLES
        /c reconstitute interview_01.docx   (deprecated — use: /c restore interview_01.docx)

--------------------------------------------------------------------------------

corpus find-source CHUNK_ID
    Look up the source document for a given vector store chunk ID. Useful
    when a search result chunk needs to be traced back to its origin.

    ARGUMENTS
        CHUNK_ID    (required) Vector store chunk UUID.

    OUTPUT FIELDS
        Source Document   Original filename
        Corpus ID         Internal corpus identifier
        Chunk Position    e.g., "3/12" (chunk 3 of 12 for that document)
        Doc Type          Document type
        Ingested At       Timestamp of ingestion
        Original Path     Absolute source path
        Text Cache        Path to plain-text cache

    EXAMPLE
        /c find-source a1b2c3d4-...

--------------------------------------------------------------------------------

corpus restore IDENTIFIER [--output PATH] [--from-store]
    Reconstruct the plain text of a corpus document. Reads from the fast
    text cache by default; falls back to reassembling chunks from ChromaDB.

    ARGUMENTS
        IDENTIFIER  (required) Original filename or corpus ID.

    OPTIONS
        --output PATH
            Write the restored text to PATH instead of printing to stdout.

        --from-store
            Force reassembly from vector store chunks even if a text cache
            exists. Useful when the cache is missing or stale.

    EXAMPLES
        /c restore interview_01.docx
        /c restore interview_01.docx --output recovered.txt
        /c restore interview_01.docx --from-store

--------------------------------------------------------------------------------

corpus update [--yes]
    Scan the source directories of all corpus files for changes. Compares
    current file content hashes against stored hashes and reports:

        [NEW]     Files found in source directories not yet in the corpus.
        [CHANGED] Files whose content hash differs from the stored hash.
        [MISSING] Corpus entries whose source file no longer exists on disk.

    After reporting, prompts for confirmation before re-ingesting changed
    files and adding new ones. Use --yes / -y to skip the prompt.

    Source directories are inferred from the original_path of existing
    corpus entries. Only files with scannable extensions (.txt, .md, .pdf,
    .docx) are considered when looking for new files.

    Relative original_path entries (from older corpus versions) are
    resolved via: (1) path as stored, (2) current working directory,
    (3) project root parent.

    OPTIONS
        --yes, -y
            Skip confirmation prompt and proceed automatically.

    EXAMPLES
        /c update
        /c update --yes

================================================================================
COMMAND GROUP: index  (/i)
================================================================================

Interactive alias: /i

index build [--force]
    Build (or rebuild) the vector store from all files currently in the
    corpus. Runs every file through the full 4-stage Cognitive Architect
    pipeline (Stratify -> Structure -> Enrich -> Synthesis). Prompts for
    confirmation before starting, as this can be time-consuming.

    OPTIONS
        --force
            Force a full rebuild even if the index appears current. (Flag
            reserved for future incremental-build logic; currently always
            triggers a full rebuild.)

    EXAMPLES
        /i build
        /i build --force

--------------------------------------------------------------------------------

index status
    Display the current status of the active project's vector store:
    collection name, distance metric, total indexed chunks, and the model
    keys configured for each pipeline stage.

    EXAMPLE
        /i status

--------------------------------------------------------------------------------

index chunks IDENTIFIER [--meta] [--pretty] [--summary]
    Display all text chunks stored in the vector index for a specific
    document.

    ARGUMENTS
        IDENTIFIER  (required) Original filename or corpus ID.

    OPTIONS
        --meta
            Show abbreviated metadata (themes, doc type) for each chunk.

        --pretty
            Pretty-print the full metadata dict and content for every chunk.
            Implies --meta.

        --summary
            Also display the holistic document summary stored with the
            chunks (generated during Stage 3).

    EXAMPLES
        /i chunks interview_01.docx
        /i chunks interview_01.docx --meta
        /i chunks interview_01.docx --pretty --summary

vector query QUERY...
    Perform a simple semantic query against the vector store and print the
    top matching chunks. Useful for quick ad-hoc lookups.

    ARGUMENTS
        QUERY   (required, variadic) Query text (space-separated tokens are
                joined into a single query string).

    EXAMPLE
        /v query what are the main barriers to adoption

--------------------------------------------------------------------------------

vector create
    Create a new, blank vector store for the project, deleting any existing
    one. Prompts for confirmation. Does not ingest any documents.

    EXAMPLE
        /v create

    EXAMPLE
        /v rebuild

COMMAND GROUP: analyze  (/a)
================================================================================

Interactive alias: /a

analyze search QUERY [--k INT] [--threshold FLOAT] [--exact] [--summary]
    Unified search command. Supports top-K similarity search, threshold-
    filtered similarity search, and exact string search via flags.

    ARGUMENTS
        QUERY   (required) Search query or exact string.

    OPTIONS
        --k INT             (default: 3)
            Return the K chunks most similar to QUERY, ranked by score.
            Mutually exclusive with --threshold and --exact.

        --threshold FLOAT   (range: 0.0 - 1.0)
            Return ALL chunks whose similarity score exceeds THRESHOLD.
            Not capped — every qualifying chunk is returned.
            Mutually exclusive with --k and --exact.

        --exact
            Case-sensitive substring match. Returns every chunk whose
            text contains QUERY verbatim.
            Mutually exclusive with --k and --threshold.

        --summary
            Also display the holistic document summary for each result's
            source file.

    EXAMPLES
        /a search "barriers to adoption"
        /a search "barriers to adoption" --k 10 --summary
        /a search "participant challenges" --threshold 0.75
        /a search "trust" --threshold 0.8 --summary
        /a search "informed consent" --exact
        /a search "COVID-19" --exact --summary

--------------------------------------------------------------------------------

analyze tools
    List all available analysis plugins with their keys and descriptions.

    EXAMPLE
        /a tools

--------------------------------------------------------------------------------

analyze clustering [--k INT] [--threshold FLOAT] [--save]
    Hierarchical Agglomerative Clustering on all chunk embeddings, followed
    by LLM Axial Coding to synthesise each cluster's themes.

    OPTIONS
        --k INT             (default: 5)  Number of clusters.
        --threshold FLOAT   (default: 0.7)  Unused by this plugin.
        --save              Write axial_theme back to chunk metadata.

    Requires: scikit-learn

    EXAMPLES
        /a clustering
        /a clustering --k 6 --save

--------------------------------------------------------------------------------

analyze anomaly [--k INT]
    IsolationForest outlier detection on chunk embeddings. Reports the K
    most semantically isolated chunks.

    OPTIONS
        --k INT   (default: 5)  Number of outliers to report.

    Requires: scikit-learn

    EXAMPLE
        /a anomaly --k 3

--------------------------------------------------------------------------------

analyze visualize
    Reduces all chunk embeddings to 2D via t-SNE and saves a scatter plot
    coloured by theme to the project directory.

    Requires: scikit-learn, matplotlib, pandas, seaborn

    EXAMPLE
        /a visualize

--------------------------------------------------------------------------------

analyze entity QUERY [--k INT] [--threshold FLOAT] [--options STRING]
    Extract named entities from chunks retrieved for QUERY.

    OPTIONS
        --k INT             (default: 5)
        --threshold FLOAT   (default: 0.7)
        --options STRING    Comma-separated entity types.
                            Example: --options "people,places,organisations"

    EXAMPLE
        /a entity "barriers" --options "people,concepts,barriers"

--------------------------------------------------------------------------------

analyze categorize QUERY [--k INT] [--threshold FLOAT] [--options STRING]
    Assign retrieved chunks to user-defined categories.

    OPTIONS
        --k INT             (default: 5)
        --threshold FLOAT   (default: 0.7)
        --options STRING    Comma-separated category names.
                            Example: --options "policy,finance,governance"

    EXAMPLE
        /a categorize "funding" --options "policy,finance,governance"

--------------------------------------------------------------------------------

analyze sentiment QUERY [--k INT] [--threshold FLOAT]
    Sentiment analysis on chunks retrieved for QUERY. Returns per-chunk
    labels and an overall summary.

    OPTIONS
        --k INT             (default: 5)
        --threshold FLOAT   (default: 0.7)

    EXAMPLE
        /a sentiment "patient experience" --threshold 0.65 --k 8

--------------------------------------------------------------------------------

analyze summarize QUERY [--k INT] [--threshold FLOAT]
    LLM-generated prose synthesis of the chunks most relevant to QUERY.

    OPTIONS
        --k INT             (default: 5)
        --threshold FLOAT   (default: 0.7)

    EXAMPLE
        /a summarize "key findings" --k 10

--------------------------------------------------------------------------------

analyze interpret [--k INT] [--threshold FLOAT]
    Synthesises all holistic document summaries into a single meta-summary
    using the LLM. Good for a project-wide overview without a specific query.

    OPTIONS
        --k INT             (default: 5)
        --threshold FLOAT   (default: 0.7)

    EXAMPLE
        /a interpret

--------------------------------------------------------------------------------

analyze topk QUERY [--k INT] [--summary]
    DEPRECATED. Use 'analyze search QUERY --k N' instead.

    EXAMPLE
        /a topk "barriers"    (deprecated — use: /a search "barriers" --k 3)

--------------------------------------------------------------------------------

analyze exact QUERY [--summary]
    DEPRECATED. Use 'analyze search QUERY --exact' instead.

        /a exact "consent"    (deprecated — use: /a search "consent" --exact)

================================================================================
PLUGINS  (direct subcommands of 'analyze')
================================================================================

    Each plugin is invoked directly as a subcommand: /a <plugin> [options].
    'analyze run PLUGIN' is a deprecated alias kept for backwards compatibility.

    SUBCOMMAND   QUERY     DESCRIPTION
    ------------ --------- ---------------------------------------------------
    interpret    No        Synthesises all holistic document summaries into a
                           single meta-summary using the LLM. Good for a
                           project-wide overview without a specific query.

    clustering   No        Hierarchical Agglomerative Clustering on all chunk
                           embeddings, then LLM Axial Coding to synthesise
                           each cluster's themes into an abstract core theme.
                           --k sets cluster count; --save writes axial_theme
                           back to chunk metadata.
                           Requires: scikit-learn

    anomaly      No        IsolationForest on all chunk embeddings to find the
                           most semantically isolated (outlier) chunks.
                           --k controls how many outliers are reported.
                           Requires: scikit-learn

    visualize    No        Reduces all chunk embeddings to 2D via t-SNE and
                           saves a scatter plot coloured by theme to the
                           project directory.
                           Requires: scikit-learn, matplotlib, pandas, seaborn

    entity       Yes       Extracts named entities from retrieved context
                           chunks. Specify entity types with --options
                           (e.g., "people,places,organisations").

    categorize   Yes       Assigns retrieved chunks to user-defined categories.
                           Provide category names with --options
                           (e.g., "policy,finance,governance").

    sentiment    Yes       Performs sentiment analysis on retrieved context
                           chunks. Returns per-chunk labels and an overall
                           summary.

    summarize    Yes       Produces a prose synthesis of the chunks most
                           relevant to QUERY. Returns an LLM-generated
                           narrative rather than raw chunks.

TOP-LEVEL COMMAND: batch-index
================================================================================

python m3.py batch-index --project NAME --corpus PATH [OPTIONS]

    Non-interactive pipeline run for scripting and automation. Ingests all
    documents in CORPUS into PROJECT's vector store and outputs a JSON
    summary to stdout on completion. Suitable for CI pipelines or scheduled
    jobs.

    OPTIONS
        --project NAME      (required)
            Name of an existing project to ingest into.

        --corpus PATH       (required)
            Path to a corpus directory or a single file. Must exist.

        --collection NAME   (default: m3_collection)
            Target ChromaDB collection name within the project.

        --doc-type TYPE     (default: document)
            Document type applied during ingestion (e.g., document,
            interview).

    OUTPUT  (stdout, JSON)
        {
          "documents_processed": <int>,
          "chunks_stored":       <int>,
          "collection":          "<collection_name>",
          "errors":              ["<error_msg>", ...]
        }

    EXAMPLES
        python m3.py batch-index --project my_study --corpus ./data/

        python m3.py batch-index \
            --project interviews \
            --corpus ./raw/interviews/ \
            --doc-type interview \
            --collection interviews_v1

INTERACTIVE MODE REFERENCE
================================================================================

Start interactive mode:
    python m3.py --go

All commands are entered with a leading '/'. The active project is shown
in the prompt and in the bottom toolbar.

COMMAND ALIASES
    /p   project
    /c   corpus
    /i   index
    /a   analyze
    /v   vector  (deprecated — use /i)

BUILT-IN COMMANDS
    /help       Show available commands and aliases.
    /quit       Exit interactive mode.
    /q          Alias for /quit.

FEATURES
    - Command history stored at ~/.monkey3/history
    - Tab completion for commands and subcommands
    - Auto-suggest from history (grey ghost text)
    - Bottom toolbar displays active project name

BATCH FILE FORMAT  (--batch FILE)
    One command per line, without the leading '/'.
    Lines beginning with '#' are comments and are ignored.

    Example batch file:
        # Set up a new project
        project create pilot_study
        corpus add "data/interviews/*.docx" --type interview
        index build
        analyze clustering --k 5 --save

================================================================================
DATA STORAGE
================================================================================

    ~/.monkey3/
    |-- config.yaml                   Global configuration
    |-- history                       Interactive mode command history
    `-- projects/
        `-- <project_name>/
            |-- corpus/               Plain-text copies of ingested documents
            |-- chroma_db/            ChromaDB persistent vector store
            `-- corpus_metadata.json  Per-document tracking and provenance

================================================================================
INGESTION PIPELINE STAGES
================================================================================

    Stage 0  Stratify
        Interview-specific. Splits Q&A exchanges into discrete turns using
        the LLM (stratify_model). Skipped for non-interview document types.

    Stage 1  Structure
        Thematic Scaffolding. Extracts 2-4 thematic codes per chunk using
        the LLM (structure_model). Stored as 'themes' metadata.

    Stage 2  Enrich
        Chunk Splitting + Hypothetical Question Generation. Splits documents
        into smaller overlapping chunks and generates a representative
        question for each chunk using the LLM (enrichment_model). Stored as
        'hypothetical_question' metadata.

    Stage 3  Synthesis
        Holistic Summary. Generates a document-level narrative summary from
        all chunks using the LLM (synthesis_model). Retrievable via
        'corpus summary' and used by the 'interpret' plugin.

================================================================================
CONFIGURATION
================================================================================

    Config file: ~/.monkey3/config.yaml

    Key settings:

    ingestion_config.known_doc_types
        List of valid document type strings for --type.
        Default: [document]

    ingestion_config.default_doc_type
        Fallback type when --type is omitted.
        Default: document

    ingestion_config.cogarc_settings
        Maps pipeline stages to model keys:
          stage_0_model  ->  stratify_model
          stage_1_model  ->  structure_model
          stage_2_model  ->  enrichment_model
          stage_3_model  ->  synthesis_model

    llm_providers
        Defines Ollama endpoints and model names for each model key.
        Default base URL: http://localhost:11435

================================================================================
QUICK-START WORKFLOW
================================================================================

    1. Start m3 in interactive mode:
           python m3.py --go

    2. Create a project:
           /p create my_study

    3. Add documents:
           /c add "data/interviews/*.docx" --type interview
           /c add report.pdf

       Or add and index in one step:
           /c add "data/interviews/*.docx" --type interview --ingest

    4. Build the vector index (runs all 4 pipeline stages):
           /i build

    5. Search and explore:
           /a search "main findings" --k 5
           /a search "barriers" --threshold 0.75
           /a search "informed consent" --exact

    6. Run analysis plugins:
           /a clustering --k 5 --save
           /a interpret
           /a anomaly --k 3

    7. Check for updated source files:
           /c update

    8. Start a dialogue session:
           /p dialogue

    9. Exit:
           /q
